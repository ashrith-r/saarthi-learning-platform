# Saarthi
<!-- impeccable:product-schema 1 -->

## Platform
web

## Users
Students preparing for exams; administrators and content editors who manage their learning materials and assessments.

## Product Purpose
Connect curriculum, lecture videos, PDF documents, resources, practice tests, personal notes and study planning in one working educational product. The user prioritizes a polished, practical, deployable demonstration supported by an accurate SRS.

## Capabilities and Constraints
The existing Node/Express/EJS/MongoDB application remains the implementation. Admins must create and edit curriculum and materials without editing source code. The user confirmed PDF uploads as well as document/video links. Changes must be reflected in student pages. Demo fixtures are isolated opt-in data, not permanent application content. Interface actions and derived statistics remain implemented in code; editable educational content belongs in the database. Interface copy uses functional page titles, features and necessary instructions, with no promotional taglines.

## Brand Commitments
The user explicitly requested full dark mode, blue and orange, no purple accent and no emojis. The current visual authority is the supplied Resq.io screenshots and https://laststack.io/: black space, cool overhead illumination and translucent interface surfaces. A procedural planet changes camera view across pages, with a stable layered star field. Spark fireworks are removed; orange marks useful actions. Motivation is conveyed visually; remove motivational taglines. Preserve task clarity in student and administrator screens.

## Evidence
Existing runtime, SRS.md, integration tests and local demo fixtures. No invented customer claims, learning outcomes or fabricated live analytics.

## Principles
Learning content is editable. Student work survives background content updates. Assessments remain private and deadline-enforced. Motion respects reduced-motion preferences. Publish controls clearly describe visibility.
